# 验证码机器学习

## 适用范围与上报策略

该功能仅用于已取得网站及数据处理授权的环境。管理员侧边栏的“机器学习”页面
控制全体在线客户端的上报方式，服务端首次部署及数据库迁移后默认关闭：

- `off`（关闭）：不上传任何验证码数据。
- `metrics_only`（仅统计）：只上传自动模型的验证码类型、模型版本、成功/失败和
  发生时间，不上传图片、答案或业务来源；人工输入和人工点选不上传、不统计。
- `samples_and_metrics`（采集样本并统计）：记录上述统计；成功时还上传图片和
  答案，失败时仍不上传图片和答案。

客户端每 60 秒刷新策略；管理员切换策略或应用模型会增加策略修订号。旧版客户端
无法识别“仅统计”时会将其视为关闭，避免误传图片；升级后的客户端才会上报纯统计。

游客模式不会显示或启用该功能；服务端尚未部署对应接口或迁移时，客户端保持
默认关闭并在管理页显示读取失败。“采集样本并统计”模式下，成功样本会先写入
当前在线账号专属的本地验证码待同步队列，再立即上传；上传成功后删除本地副本，
断网或上传失败时保留并可通过侧栏“验证码待同步”按钮重新上传。切换为“关闭”或
“仅统计”后暂停上传并隐藏该按钮，重新启用采集后继续处理原账号的待同步样本。
纯统计上报不写入该队列；瞬时后台任务仍限制为 64 个，避免挤占业务客户端内存。

## 采集规则

客户端在网页确认验证码已经通过后立即提交成功样本，不再等待后续业务结果返回：

- 数字验证码：PNG/JPEG 图片及四位数字 `{"value": "1234"}`。
- 文字点选验证码：PNG/JPEG 图片、题目文字顺序和相对坐标（`x/y` 均为
  `0..1`），坐标不依赖客户端窗口尺寸。
- 自动识别使用的灰度化、补边、拉伸、锐化、二值化或分块增强图片只在本机内存中
  参与识别；验证码通过后采集的是处理前的网页原始截图，不上传识别处理图。
- 自动识别和人工接管分别记录模型版本及 `assisted` 标记；线上准确率只聚合
  `assisted=false` 的自动识别尝试，人工输入或人工点选不进入准确率分母、分子。
- “仅统计”不会为成功或失败尝试采集、编码或上传图片和答案。服务端根据验证码
  类型推导内部来源，仅保存类型、模型版本、是否人工、发生时间和成功/失败标记，
  不关联账号或设备，用于计算当前模型的线上成功率。
- “采集样本并统计”下，失败尝试同样不保存或上传图片和答案。
- 服务端按“类型 + 图片 + 标准化答案”的 SHA-256 指纹去重。重复成功尝试会计入
  线上成功率，但不会重复占用数据集空间。

侧栏在线状态卡在采集模式下将原按钮区域等分为业务“待同步”和“验证码待同步”；
其他策略下保持原单按钮样式。验证码待同步数量来自客户端 SQLite，仅包含当前账号
尚未被服务器接受的成功样本。服务端接受后对应本地记录立即删除。

单张图片上限为 1 MB。服务端仅接受 PNG/JPEG 文件签名、严格答案结构和受支持
来源；管理员操作会写入审计记录。

## 管理页面指标

- 数据集数量与占用空间：每 5 秒刷新，并分别显示数字和文字点选样本。
- 当前模型成功率：真实客户端尝试中，该模型版本的成功次数 / 尝试次数。
- 数字验证码和文字点选验证码分别统计准确率；模型表只展示内置 `ddddocr` 和
  服务端仍保存模型文件的候选、当前及历史版本。没有对应模型文件的孤立识别记录
  仍保留在服务端审计数据中，但不会伪装成一行可操作模型。
- `human-manual` 等人工版本不会出现在模型列表或准确率中。模型表可按数字/文字
  点选筛选；顶部准确率始终显示当前应用模型，选中其他模型只在对应表格行和提示区
  显示其统计。选择“刷新所选统计”可从服务端重新聚合该版本的自动识别次数和准确率，
  不会删除或清零历史识别记录。
- 候选模型识别率：训练时固定、确定性的 20% 留出集结果，不包含后续线上尝试。
- 数字模型按四位数字全部一致才算一次正确。
- 点选模型按题目文字对应区域的完整序列全部一致才算一次正确；检测框仍由内置
  检测器提供，因此此数值不是端到端网页通过率。

样本量过少时训练按钮会提示：数字至少 20 张，文字点选至少 30 张。达到最低值
只代表可以执行训练，不代表模型已经适合生产应用；管理员应比较留出集准确率，
再在授权环境进行实际验收。为限制管理员电脑的训练内存和模型体积，单次每种类型
最多按样本指纹确定性选取 5000 张；候选模型指标会同时记录可用数与实际选取数。

## 人工点选样本采集

文字点选验证码优先从网页图片的 `data:`/canvas 原始内容生成 PNG，不保存包含
`.point-area` 编号圆点的页面合成截图；无法直接读取原图时会先临时隐藏圆点再截图，
随后立即恢复页面。题图、题目、图片代次和点击坐标按同一验证码关联，失败刷新后只
清理旧题事件，用户快速点选的新题仍会保留。

日志中的“验证码点击错误”是页面尚未返回成功结果时的即时提示，并不立即把样本判为
失败。后续出现业务结果时保存原题成功样本；只有检测到题图像素、题目或代次已变化，
程序才丢弃上一题并进入下一轮“等待用户点完验证码”。人工点选样本仍可用于训练，但
人工成功或失败不会计入自动识别准确率。

## 模型生命周期

v1.1.0 的标准模式使用 `hog-linear-svm-v1`：数字验证码对完整原图提取一份
64×64 HOG 特征，再训练四个位置的 one-vs-rest 线性 SVM，不按等宽切分字符；文字
点选对成功坐标附近的候选字符裁图提取 HOG，再训练线性 SVM。标准模型保存在安全
NPZ 容器中，数组固定为字符串、`int32` 和 `float32`，加载时禁用 pickle，并严格
校验成员、形状和大小。旧 `knn-pixels-v1` 只保留历史读取能力，升级后不会再训练、
上传、激活、下载或从本机活动缓存恢复。

可选强化模式使用 `tiny-cnn-onnx-v1`。强化训练器以本机管理员安装的平台专用
`.inttrainer` 单文件组件运行；不需要配套 JSON，组件本身不上传服务端，也不由服务端分发。
Windows x64 与统信 UOS ARM64 使用同一外层包格式和命令协议，但必须分别在目标平台
本机构建。安装会校验平台、清单、文件 SHA-256 并执行自检；SHA-256 只用于检测损坏，
管理员应从可信本地来源取得组件。强化训练输出是原始 ONNX，卸载训练组件不会删除样本、候选模型或已经训练
完成的 ONNX 模型。组件不可用时训练模式自动回落为标准模式。

文字点选模型的训练和业务推理共用同一套原图裁剪、等比缩放、黑边填充和通道排列逻辑；
靠近图片边缘及极小图片也遵循同一规则。内置检测器仍可使用锐化整图查找候选框，但
HOG/CNN 分类器接收网页原始截图和同一组候选框，避免训练图与生产推理图的像素分布不一致。

训练先在管理员客户端本地完成，再将候选模型、样本数、留出集结果和 SHA-256 上传
服务端。模型表显示每个版本的实际算法；服务端只接受上述标准/强化算法及其对应
NPZ/ONNX 产物，并校验 `training_mode` 和可选 `trainer_version`。模型类型、版本、
算法和 SHA-256 必须同时与产物一致；客户端缓存、服务端激活及下载都会重复校验，
强化 ONNX 还会检查 metadata、opset、图结构、输入输出形状和本机推理结果。

候选模型不会自动影响业务。管理员选择“应用所选模型”后：

1. 同类型旧模型变为历史版本；
2. 新模型成为当前版本，策略修订号增加；
3. 客户端下载模型并核对 SHA-256；
4. 校验和解析均成功后才原子写入本机模型缓存并开始使用；
5. 下载或校验失败时继续使用内置 `ddddocr`，不会加载不可信模型。

当前应用模型不能删除；候选或历史模型可删除，样本数据不会随模型删除。管理员
也可按所选类型恢复内置 `ddddocr`，原自定义模型转为历史版本并保留，便于再次
应用或对比。客户端离线重启时可继续加载上次已校验的当前模型；重新连接并发现
管理员已恢复内置模型后，会清除“当前自定义模型”标记。

候选、当前和历史自定义模型可以单独设置显示名称。重命名只改变管理页面显示的
别名，不改变内部版本号、模型文件、SHA-256 或历史识别统计；内置 `ddddocr` 没有
可编辑的模型记录，不能重命名。

## 数据集导入与导出

管理员一次导出全部数据，ZIP 顶层按验证码类型使用 `numeric` 和 `click` 目录；
即使某一类暂时没有样本也保留对应空目录。导出的原 ZIP 可以直接重新导入，旧版
`images/...` 及中文目录数据集继续兼容。训练某一类型时客户端仍可在后台请求该
类型的样本子集。压缩包结构：

```text
manifest.json
numeric/<sample-uuid>.png
numeric/<sample-uuid>.jpg
click/<sample-uuid>.png
click/<sample-uuid>.jpg
```

`manifest.json` 的 `schema_version` 当前为 `1`，`categories` 同时记录数字与文字
点选目录、显示名称和样本数量；每条样本包含：

```json
{
  "id": "UUID",
  "captcha_type": "numeric",
  "source": "transport_numeric",
  "image": "numeric/UUID.png",
  "image_mime": "image/png",
  "answer": {"value": "1234"},
  "model_version": "human-manual",
  "captured_at": "2026-07-30T10:00:00+00:00",
  "fingerprint": "SHA-256"
}
```

导入包上限为 100 MB（压缩前请求体及解压后内容均校验），拒绝路径穿越、重复
路径、超量文件和无效清单。读取器兼容旧版 `images/...`、中文目录、Windows
反斜杠、`./` 前缀及带 UTF-8 BOM 的清单；导入会重新检查图片签名、答案和指纹，
不信任清单中的原始 ID 或指纹，页面会分别报告新增、重复和跳过数量。

机器学习页的样本表支持按类型筛选、分页、双击查看图片以及 Ctrl/Shift 多选删除。
图片会在后台下载，缺图、样本已删除或服务端接口版本过旧时会显示对应提示。删除只
影响选中样本及后续导出/训练，不删除对应的自动识别准确率历史尝试。

## 接口

普通在线账号：

- `GET /api/v1/captcha/policy`
- `POST /api/v1/captcha/attempts`
- `GET /api/v1/captcha/models/{numeric|click}/current`

管理员：

- `GET /api/v1/admin/ml/overview?captcha_type=&model_version=`
- `GET /api/v1/admin/ml/samples?captcha_type=&model_version=&limit=&offset=`
- `GET /api/v1/admin/ml/samples/{id}/image`
- `DELETE /api/v1/admin/ml/samples`
- `PATCH /api/v1/admin/ml/policy`
- `GET /api/v1/admin/ml/dataset/export`
- `POST /api/v1/admin/ml/dataset/import`
- `POST /api/v1/admin/ml/models`
- `PATCH /api/v1/admin/ml/models/{id}`（仅修改显示名称）
- `POST /api/v1/admin/ml/models/{id}/activate`
- `POST /api/v1/admin/ml/models/{numeric|click}/use-builtin`
- `DELETE /api/v1/admin/ml/models/{id}`

`PATCH /api/v1/admin/ml/policy` 使用
`{"upload_mode":"off|metrics_only|samples_and_metrics"}`。部署新版本后必须执行
Alembic `upgrade head`，以创建或升级验证码策略、尝试、样本和模型表，并将仍处于
当前状态的旧 KNN 模型归档。
数据库备份会随现有 PostgreSQL 全量备份流程包含这些数据；导出的 ZIP 仍应按
敏感授权数据加密保管。
