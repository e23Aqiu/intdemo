# 同步协议与隐私边界

## 同步项

`POST /api/v1/sync/push` 每批最多 100 项，单项最大 64 KiB：

```json
{
  "schema_version": 1,
  "event_uid": "UUID",
  "kind": "activity_event",
  "entity_id": "client-stable-id",
  "revision": 1,
  "occurred_at": "2026-07-27T10:00:00+08:00",
  "payload": {}
}
```

`kind` 只允许：

- `activity_event`
- `workflow_batch_snapshot`
- `workflow_run_snapshot`

活动事件按账号和 `event_uid` 幂等；快照只接受更高修订，`succeeded` 不能回退
到运行态。永久非法项返回 `rejected/retryable=false`，客户端移入隔离区。

## 允许载荷

- 活动：指标键、整数总数量、可选黄牌数量、业务日期、安全来源标识、安全任务
  ID、行数，以及全量和黄牌违规原因数量汇总。
- 批次：状态、SHA-256 输入指纹、日期、开始/完成时间、有效/暂停/总用时、
  重试次数及指标计数。
- 运行：批次 ID、状态、步骤序号、开始/结束时间、有效/暂停/总用时和重试数。

服务端以严格白名单拒绝额外字段；嵌套汇总只允许整数。客户端在同一 SQLite
事务中先剥离本地明细再写 outbox。

黄牌数量是总数量的子集，不能大于总数量。旧活动事件没有黄牌数量时，客户端按
“总数量即黄牌数量”读取，使升级前的历史统计继续全部归入黄牌口径。车牌及逐行
筛选结果仍只留在本机，服务端只保存两个口径的聚合数量。

v1.1.2 客户端发布前必须先升级服务端，否则旧服务端的严格白名单会拒绝
新增黄牌汇总字段。新字段在请求中可选、数据库列可空；v1.1.0 和 v1.1.1
客户端可继续上传不含该字段的旧载荷，拉取新载荷时也会忽略未识别的扩展字段。

v1.2.0 在账号对象和离线授权中增加 `account_type`、`data_scope`、`road_id`、
`road_name`，并增加只读路段列表接口。原有 `role` 仍只返回 `admin/user`，原有
`stats_scope` 仍只返回 `own/all`：路段管理员对旧客户端表现为普通用户，“本路段”
对旧客户端表现为“本人”。服务端根据登录设备记录的客户端版本决定同步范围；
v1.1.0/v1.1.1 设备不会收到无法在旧 SQLite 约束中表示的 `road` 范围，未上报版本
的集成也按 v1.1.2 保守处理。`0014` 只增加字段和“广深高速”路段；`0015` 将既有
测试账号从路段中脱离并把不适用的“本路段”范围降为“本人”。两次迁移都不修改既有
账号密码、启停状态、令牌版本或刷新会话。测试账号直属全局管理员，路段管理员的
账号列表、管理权限和“本路段”数据范围均不包含测试账号。路段分类由同名路段管理
员账号拥有；没有路段管理员的内部路段不会出现在可分配列表。中心站和测试账号可为
“未分配”，此时只由全局管理员管理；v1.1.0/v1.1.1 管理端新建中心站未携带路段
字段时也保持未分配。路段管理员账号自身不参与业务统计：服务端会确认其旧客户端
上报项以便清空 outbox，但不落活动、批次或运行统计；拉取和快照也会排除该账号现有
历史数据。客户端本地汇总同样按 `account_type` 排除路段管理员，因此条数、占比、
效率、违规原因和站点分布均只使用范围内的中心站数据。

## 业务同步永不上传

原始 Excel、文件名和路径、逐行车辆数据、车牌、运输证号、公司、法人、
地址、电话、Cookie、浏览器登录状态、运行日志和步骤错误明细。

上述边界专指 `/sync/push` 业务同步通道。授权验证码学习使用独立接口、独立
数据库表和管理员三档策略，默认关闭；它不会携带 Excel、车辆、公司、路径、
Cookie 或日志。“仅统计”只发送验证码类型、模型版本、结果、人工协助标记和
时间；“采集样本并统计”下仅成功验证码可附带挑战图片及答案，失败尝试不得携带
图片或答案。协议、留存和导入导出格式见
[验证码机器学习](CAPTCHA_LEARNING.md)。

## 拉取

WebSocket 仅发送全局修订变化通知，不携带业务数据。客户端随后调用
`GET /sync/pull?after_revision=N`；30 秒轮询为兜底。v1.2.0 以 `data_scope` 为准：
`own` 只返回本人，`road` 返回同一所属路段，`all` 返回全部；管理员始终为全部。
兼容字段 `stats_scope` 会把 `road` 投影为 `own`。账号管理范围与数据查看范围相互
独立：路段管理员即使被全局管理员授予全部数据，也仍只能管理本路段中心站。

管理员调整账号所属路段时，服务端追加 `road_membership_changed` 修订。只有原路段
和新路段中使用 `data_scope=road` 的 v1.2.0 客户端会收到 `refresh_scope=true`，随后
立即重取快照；移出路段的历史缓存会被清除，移入路段的既有历史会被补齐。旧客户端
会忽略该扩展修订，其服务端有效范围仍按“本人”降级。

永久删除最后一个路段管理员时，服务端将该路段中心站全部改为未分配，把仍使用
`road` 的中心站范围收窄为 `own`，并为每个中心站追加账号与路段关系修订；新建同名
管理员不会自动收编这些中心站。归档可恢复，因此归档本身不解除路段关系。

账号归档和统计重置写入 `change_log`。重置产生带时间的墓碑，服务器永久拒绝
更早的离线项，客户端同时清除对应缓存和隔离旧 outbox。
